# 梯度传播核查流程

用途：模型或训练循环完成后、长时间训练前，以及 loss、冻结策略或梯度估计方法变更后，由研究者与 AI 共同核查。

**顺序：算法意图 → 目标与数据 → 计算图 → 梯度数值 → 参数更新 → 最小训练。**

本文件是可复用流程，尚未对任何项目执行核查。

## 0 · 明确预期梯度路径

研究者与 AI 先共同填写下表；AI 根据论文、项目定义与代码提出预期，研究者确认涉及算法选择的部分。

| Loss / 更新阶段 | 应收到梯度的参数组 | 应停止梯度的位置 | 应由哪个 optimizer 更新 | 依据 |
| :--- | :--- | :--- | :--- | :--- |
| 待填写 | 待填写 | 待填写 | 待填写 | 公式 / 论文 / 设计说明 |

区分参数冻结与阻断输入梯度；明确 target、advantage、共享编码器、交替优化和采样操作的处理。不要默认所有路径都应反传。

## 1 · 检查目标与数据

**AI 执行：**

- 核对 loss 的公式、正负号、各项权重和优化方向。
- 记录预测、标签、mask 的 shape、dtype、device；核对每个轴的语义，排除意外广播。
- 检查 sum/mean、有效样本或 token 的分母、梯度累积的缩放。
- 检查除零、log(0)、溢出等；在执行无效运算前排除无效输入，不能只在结果上加 mask。

**研究者判断：**这些目标、权重、mask 和数据配对是否代表实际研究问题？

**证据：**一个小 batch 的形状、loss 分项及其计算依据。

## 2 · 检查计算图

**AI 执行：**

- 按第 0 步逐条核对 requires_grad、detach、no_grad、inference_mode、重新构造张量和外部库边界。
- 检查离散采样、argmax、整数索引：哪些路径可微，哪些需要梯度估计器。
- 区分未计算梯度、梯度为零和梯度未保存；非叶子张量的 .grad 默认可能不保存。
- 对关键 loss 分别检查到预期参数组的连接，避免总 loss 掩盖某个分支的断图。
- 检查原地修改是否破坏反向所需的中间值；eval() 不等于关闭自动微分。

**研究者判断：**实际路径与算法预期是否一致？有意阻断的路径需说明理由。

**证据：**loss → 参数组的连接表，异常处附代码位置。

## 3 · 检查梯度数值

**AI 执行：**在小规模、固定输入的运行中，于反传后、清零前记录：

- 各预期参数组的 grad 是否存在、是否有限、范数及零梯度比例。
- 异常层的激活范围、饱和或长期不激活情况；比较多个代表性 batch。
- 分别记录裁剪前后的梯度，避免裁剪隐藏异常。
- 使用混合精度时，检查或裁剪前先按所用框架正确 unscale，并记录是否跳过更新。
- 多项 loss 分别检查梯度尺度；疑似冲突时再比较梯度方向。

**研究者判断：**小梯度是否符合任务和参数尺度？不能用统一阈值认定所有层都应有非零梯度。

**证据：**梯度统计表；异常项附复现输入与运行条件。

## 4 · 检查实际参数更新

**AI 执行：**

- 核对 optimizer 参数组、重复或遗漏参数、学习率、step 与清零顺序。
- 在一次更新前后保存参数副本，对比应更新与应固定的参数组，报告变化量。
- 若梯度为零但参数变化，检查动量、optimizer 状态和权重衰减；区分 grad=None 与零张量。
- 检查冻结与交替训练时是否残留旧梯度；单独检查 BatchNorm 等缓冲状态变化。

**研究者判断：**参数变化是否符合第 0 步，而非只看 backward() 是否成功。

**证据：**参数组、梯度范数、更新量、学习率和冻结状态对照表。

## 5 · 最小训练与针对性验证

- 在小数据上短跑，观察目标、参数变化与梯度统计是否一致。适合时尝试拟合小批量；单步 loss 下降不是通用通过标准。
- 自定义 backward 或可疑的平滑确定性模块：用 gradcheck 或有限差分检查小规模输入，记录精度、步长与容差；避免在不可导点作直接比较。
- RL 的策略梯度、STE、随机估计器与有意 stop-gradient：按各自理论预期验证偏差/方差和路径，不能机械地要求匹配整个前向函数的有限差分。
- 量子项目：先在可控的小规模模拟中核对梯度，再检查有限 shots、噪声与参数偏移规则的适用条件。

这些检查提供局部证据；完整训练中的稳定性与泛化仍需实验评价。

## 输出记录

AI 对每项标记：**通过 / 失败 / 未验证 / 不适用**，并提供：

1. 代码提交、依赖版本、数据、种子、运行命令及精度设置。
2. 预期路径与实际结果、梯度和参数更新证据。
3. 异常位置、最小复现、原因假设与修复建议。
4. 尚需研究者判断的算法问题，以及尚未覆盖的边界。

只有实际执行且证据符合预期才标为通过。研究者核对目标与梯度路径，AI 修复实现问题后重跑受影响的检查。

## 给 AI 的调用指令

> 按本流程核查当前项目的梯度传播。先根据算法与代码列出各 loss 应更新的参数组及 stop-gradient 边界，再用最小运行检查目标形状、计算图、梯度数值与实际参数变化。对每项提供证据和状态；不能运行的项目标为未验证。涉及算法意图的歧义请列给我判断，不要通过删除 detach、扩大 requires_grad 范围等方式盲目恢复梯度。修复后重跑相关检查。
